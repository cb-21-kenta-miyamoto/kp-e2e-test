# 改修テストシート（ミドルバック FMT）の構造

PD / QA が実施に使う**正式様式**のブック。E2E の `【E2E】ケース一覧・実施記録`（4 タブ）とは別物。

| | E2E 実施記録 | 改修テストシート（本書）|
| --- | --- | --- |
| 誰が使うか | AI 実施エージェント | PD / QA |
| タブ構成 | 4 タブ固定 | **1 ブロック = 3 枚組**（ディシジョンテーブル / 設定マスタ / テストケース）|
| ケースの持ち方 | 1 行 1 ケース（平坦）| 観点 → 掛け合わせ → 転置 → ケース の 4 層 |
| 作る skill | `e2e-prepare` | `mb-testsheet-build` |

`IMP_KP001350` の実物: [【kpiee】改修テスト（ミドルバック）_レポートセルコメント](https://docs.google.com/spreadsheets/d/1YzUu9k57YmBRgwB_c-hJ81xm87-knFGNJmq2-NtH_Ik/)
（25 ブロック / 524 ケース）。手順の正典は [dx-kpiee#18721](https://github.com/f-scratch/dx-kpiee/issues/18721)。

---

## 1. 4 層

**1 改修 = 1 ブック。** 上から下へ機械的に落ちる。

```
観点サマリ（1枚）
  ├ ■観点マスタ                  24行固定。漏れチェック用のカテゴリ表。改修ごとに書き換えない
  ├ ■ケース作成観点と設定パターン   ブロック登録簿
  └ ブロックごとの ■確認観点詳細 / ■パターン観点詳細   ← ブロック文書の「## 2. 観点サマリー」が入る
      ↓
ディシジョンテーブル_<ブロックID>   ← 観点サマリの2表を貼り、掛け合わせに ○ を打つ。1列 = 1ケース
      ↓
設定マスタ_<ブロックID>             ← 座標を XMATCH で自動導出し、FILTER で DT を転置（非表示にする）
      ↓
テストケース_<ブロックID>           ← 実施と記録の単位
```

`<ブロックID>` はブロック文書の ID（`SPEC-1` 〜 `MB-10`）をそのまま使う。

## 2. 層をつなぐ数式

読み違えやすいので実物を残す。

| どこ | 式 | 意味 |
| --- | --- | --- |
| DT 下段のラベル行 | `=iferror(INDEX($D<VS>:$D, match("○", G<VS>:G, 0)), "-")` | その列で最初に `○` が付いた行の `観点No.` |
| DT の `C` 列 | `=COUNTA(UNIQUE($E$7:$E<row>))` | 軸グループの通し番号 |
| 設定マスタ `G6`/`G7`/`G10` | `=XMATCH("パターン観点名", INDIRECT("'ディシジョンテーブル_"&F3&"'!E1:E"))` 等 | **座標は自動導出** |
| 設定マスタ `G11` | `=MAX(MAP(SEQUENCE(...), LAMBDA(row_num, XLOOKUP("*", ...))))` | ケース数も自動 |
| 設定マスタ 本体 | `=FILTER(INDIRECT(DT のパターン列), 観点名列 = D$15, その列の ○ 列 = "○")` | DT の転置 |
| テストケース `実施目的` | `=VLOOKUP($M18, INDIRECT("'ディシジョンテーブル_"&$G$1&"'!$D$1:$F"), 2 or 3, false)` | `観点No.` で DT 下段を引く |
| テストケース `テストパターン` | `=iferror(VLOOKUP($L18, INDIRECT("'設定マスタ_"&$G$1&"'!$C$15:$W"), N$14, false), "-")` | `パターンNo.` で設定マスタを引く |
| テストケース `#` | `=ROW()-ROW($D$17)` | 自動連番 |
| テストケース `確認する対象`/`内容` | `=F18` / `=G18` | **既定の式。上書きしてよい** |
| テストケース `■事前準備` の列指定 | `=SUBSTITUTE(ADDRESS(1,MATCH("IT実施フラグ",A15:BQ15,0),4),"1","")` | 列記号も自動 |

## 3. ここから来る制約

> [!IMPORTANT]
> 1. **1 列 = 1 ケース = 1 期待値 = 1 確認観点。** `match` が 1 つ目しか拾わないので、
>    DT 下段の `○` を 1 列に 2 つ打っても 2 個目は無視される
> 2. **1 列につき、1 つのパターン観点名グループの `○` は 1 つだけ。**
>    2 つ打つと 設定マスタ の `FILTER` が配列を返して壊れる
> 3. **`観点No.` は DT 下段の通し番号。** 観点マスタ（24 分類）ではない
> 4. **シート名の接尾辞と `設定マスタ!F3` / `テストケース!G1` は完全一致させる**
>    （`="'ディシジョンテーブル_"&F3&"'!"` で参照文字列を組むため）

## 4. テンプレートの容量

`ディシジョンテーブル_×××` / `設定マスタ_×××` / `テストケース_×××` を**複製して広げる**。
新規作成すると関数・入力規則（`○` のプルダウン）・条件付き書式・罫線が付かない。

| | テンプレート | `IMP_KP001350` の最大 |
| --- | ---: | ---: |
| DT パターン行 | 33 | **70**（`SPEC-1`）|
| DT 掛け合わせ列 | 43 | **60**（`SPEC-1`）|
| DT 確認観点行 | 8 | **12**（`MB-1`）|
| 設定マスタ / テストケース の軸列 | 5 | **19**（`SPEC-1`）|
| テストケース 行 | 40 | **60**（`SPEC-1`）|

**行・列の増減は `insertDimension` / `deleteDimension` に `inheritFromBefore: true` を付ける。**
入力規則・条件付き書式・罫線が全部継承される（実測で確認）。

## 5. 複製直後に壊れているところ

**参照ブックを複製した直後、必ずこの 3 つを踏む。**

| # | 症状 | 直し方 |
| --- | --- | --- |
| 1 | `SheetURLMap` が**複製元ブックの URL** を指したまま | 全タブぶん `シート名 → https://.../edit#gid=<sheetId>` に張り替える。`ケースリンク` と `テスト概要` の `URL` 列が全滅している |
| 2 | `テスト概要!D28` の `=getSheetsWithWord()` が `#REF!` | Apps Script が紐づいていない。**シート名を直接書けば** `ケース数` / `IT数` / `URL` は動く |
| 3 | `テスト概要` の `■テストケースリンク` が 10 行しかない | ブロック数まで広げる。**`計` 行の `SUM(Q28:R37)` は挿入位置が範囲外だと伸びない**ので手で直す |

## 6. 作業中に踏む落とし穴

> [!WARNING]
> **`設定マスタ` の座標ブロック（`F3` と `F6:G11`）は観点列 `D`〜`H` と重なっている。**
> 軸が 5 未満のときに列を削除すると座標が消えて全部 `#REF!` になる。
> **列は削除せず、余った観点列の中身を空にする。**
> 軸が 5 を超えるときは `I` 列の前に挿入し、`D` 列の式を `copyPaste`（`PASTE_NORMAL`）で複製する
> （相対参照 `D$15` が列ごとにずれて正しい式になる）。

- **テストケースの `テストパターン` 列を増やしたら、行 15 の結合を張り直す。** 自動では伸びない
- **書式を `copyPaste` で移すとき、コピー元の行番号をハードコードしない。**
  誰かが 1 行挿入していると、ヘッダー行とデータ行が 1 つずれる。
  `##` / `###` / `ID` を検索して引く
- **`設定マスタ` の `#N/A` は仕様。** 「その軸がそのケースでは非該当」を表す。
  テストケース側は `iferror(...,"-")` で `-` になる
- **DT の灰色の帯は `=ISEVEN($C$7:$C…)` の条件付き書式。** `C` 列に
  `=COUNTA(UNIQUE(...))` を入れると軸グループごとに白/灰が切り替わる。手で塗らない
- **Sheets API で読んで書き戻すときは `valueRenderOption=FORMULA`。**
  既定の `FORMATTED_VALUE` だと層を結ぶ関数と `HYPERLINK` が計算結果に置き換わって壊れる
- **`○` はプルダウン。** 手で打たず入力規則から選ぶ

## 7. FMT ルール（`FMTチェックシート` から効くもの）

| # | ルール | なぜ |
| --- | --- | --- |
| 4 | セル結合をしない（テストケースの中も、結果記入欄のヘッダーも）| フィルタが使えなくなる／合否列が取得できなくなる |
| 5・6 | `#` は半角、ケース番号は半角・連番・ケース以外の行に入れない | GAS が最終行と最大値で数える |
| 7〜9 | PD 側は `PDx回目`、QA 側は `1回目`/`2回目`、**最終列は `最終実施`** | GAS が列名で探す |
| 9 | **`設定マスタ_*` と `*_×××` は非表示にする** | 実施に不要な中間成果物 |
| 11〜13 | `アカウントのログインコード` / `合否` の入力規則・条件付き書式が最新か | `リスト` シートを見る |
| 15 | **実施対象外のタブに「テストケース」を含む名前を付けない** | ケース全量に数えられる |
