# NG フォームへの投稿

組織共通の **NG 登録フォーム**へ、E2E で出た NG を投稿するための仕組み。
`e2e-ng-report` から参照する。

## なぜ中間ブックが必要か

**AI からフォームへ直接投稿できない。** 試した経路と結果:

| 経路 | 結果 |
| --- | --- |
| `viewform` を HTTP で叩く | 401。ログイン必須（社内フォーム） |
| `formResponse` へ POST（Bearer トークン付き） | 401 |
| Google Forms API (`forms.googleapis.com`) | 403。**そもそも回答の作成に非対応**（読み取り専用） |
| Apps Script `FormApp.createResponse().submit()` | **通る。** ただしフォームの編集権限が必要 |

残るのは Apps Script だけ。Apps Script は**人のアカウント権限で動く**ので、
「AI が下書き → 人が確認 → 人の権限で投稿」という形に自然に落ちる。

```
AI ──(Sheets API)──▶ 【E2E】NG管理 の NG一覧 に 1 行書く
                          │
                          │ 人が内容を確認して『送信』にチェック → メニューを押す
                          ▼
                     Apps Script（人の権限で動く）──▶ NG フォーム
                                                        │
                                                        ▼
                                        【kp】NG一覧「【編集厳禁】NGフォーム」タブ
```

| | |
| --- | --- |
| 中間ブック | [【E2E】NG管理](https://docs.google.com/spreadsheets/d/1XN-cwiwbl22axv0vmzEhrXDAAr8bi9DDgy85SkVjDsg/edit) |
| スクリプト | [`apps-script/NGForm.gs`](../apps-script/NGForm.gs) |
| フォーム（回答用） | `/forms/d/e/1FAIpQLSdwLHKQb4_c67…/viewform` |
| フォーム（編集用） | `/forms/d/1_lwMxYz7d8i5yWqpplXalqm…/edit` |
| 回答先 | 【kp】NG一覧 の `【編集厳禁】NGフォーム` タブ |

## フォームの ID は 2 つある。取り違えない

| | URL の形 | 用途 |
| --- | --- | --- |
| 回答用 ID | `/forms/d/e/1FAIpQLS…/viewform` | 人が回答する。誰でも開ける |
| 編集用 ID | `/forms/d/<別の文字列>/edit` | `FormApp.openById()` が要求するのはこちら |

**この 2 つは相互に変換できない。** 回答用 URL しか手元に無いとき、Drive を名前で探すのは
当てにならない（実際に別フォームを掴み、項目数 7 と 25 の食い違いで気づいた）。

**確実な導出経路は回答シートから引くこと。** 回答が流れ込むシートはフォームに紐づいているので
`Sheet.getFormUrl()` が編集用 URL を返す。`form_()` が
**「フォーム項目」タブの `B4` が空なら自動でこれをやる。**

## メニューは 2 つだけ

| メニュー | 関数 | 何をするか |
| --- | --- | --- |
| フォームの項目を取得する | `loadForm` | 質問を「フォーム項目」タブへ並べ、選択肢を NG一覧 のドロップダウンにする |
| チェックした行を送信する | `sendChecked` | チェック済みで未送信の行をまとめて投稿する |

**表に出る関数は `onOpen` / `loadForm` / `sendChecked` の 3 つだけ。**
かつては 33 関数あり、メニューに 7 項目並んでいた。押す順序を覚えないと使えず、
「準備する」「項目を読み込み直す」「選択肢を反映する」の違いを利用者に説明できなかった。

| 消したもの | どこへ入れたか |
| --- | --- |
| `prepare` / `listFormItems` / `syncChoiceValidation` | **`loadForm` に統合。** 取得と反映を分ける理由が無い |
| `findFormIdFromResponseSheet` | `loadForm` の中。B4 が空なら回答シートから自動で引く |
| `dryRunCheckedRows` | **`sendChecked` に統合。** 全行を検証してから送るので検証専用の操作が要らない |
| `diagnose` / `verifyTarget_` | エラーメッセージに畳んだ。**詰まる前に説明する**ほうがよい |
| `onEditHandler` / `ensureTrigger_` | **廃止**（下記） |

### `onEdit` トリガーを廃止した

チェックした瞬間に投稿する作りをやめ、**メニューを押したときだけ送る**ようにした。

- トリガーは**二重投稿の原因だった**。トリガーと手動送信が競合し、1 行から 2 通出た
- 承認が要るインストール型トリガーなので、セットアップが 1 手増える
- **フォームの回答は取り消せない。** チェックした瞬間に飛ぶのは危ない

`loadForm` は残っている古いトリガーを削除する。

> [!NOTE]
> **簡易トリガー（`function onEdit(e)`）ではフォームを触れない。**
> 外部サービスへのアクセスに承認が要るため。だから「チェックで自動送信」は
> インストール型トリガーが必須で、そのぶん構成が重くなる。

## フォームの構造（25 項目）

**セクション区切り（`PAGE_BREAK`）が 3 つあり、デバイスの回答でページが分岐する。**
`PAGE_BREAK` は回答を持てないので対応列は空のままにする。

```
お名前 / 検知したデバイス
├─[PAGE_BREAK] PC       … アプリ種別（PC） / OS
├─[PAGE_BREAK] モバイル端末 … アプリ種別（モバイル） / OSバージョン / 端末 / 端末名 / アプリバージョン
└─[PAGE_BREAK] NG報告    … 再現デバイス / テスト種別 / バグ検知環境 / 本番環境での再現有無
                          / インシデントレベル / 開発対象ID / テストケースリンク / NG事象
                          / 再現方法 / 証跡（画像・動画）/ 事象が起きている時間
                          / フロントNGフラグ / リリースSprint（起票時）
```

- **`証跡（画像・動画）` は `TEXT`。** Drive のリンクを文字列で送れる
  （`FILE_UPLOAD` なら Apps Script から投稿する手段が無く、この設計が成立しなかった）
- PC で起票する限り、モバイルページの必須項目は**埋めなくてよい**（下記）

### 分岐先ページの「必須」は必須ではない

`アプリ種別（モバイル）` `OSバージョン` `端末` `アプリバージョン（ビルド番号）` は
**フォーム上は「必須」だが、`検知したデバイス = PC` を選ぶとそのページに入らない**ので
要求されない。実回答で裏が取れる。

| 検知したデバイス | モバイル系 4 項目の埋まり | 件数 |
| --- | --- | --- |
| PC | **0 / 4** | **1431** |
| PC | 1 / 4 | 2 |
| モバイル | 3〜4 / 4 | 566 |

`FormResponse.submit()` は必須チェックをしないので、空のまま通る。

> [!IMPORTANT]
> **必須フラグだけを見て送信を止めてはいけない。**
> `isRequired()` は「そのページに来た人にとって必須か」しか表さず、
> ページ分岐を知らない。フラグだけで止めると、送れるはずの行が止まる。
>
> `buildResponse_` は 2 段構えにしてある。
> **1 段目で全項目の値を出し、セクション（`PAGE_BREAK`）ごとに使われているかを見る。**
> セクションに 1 つも値が無ければ、そのセクションごと使わないと判断して必須を問わない。
> 逆に 1 つでも埋まっていれば、同じセクションの必須の空は本当の不備として止める。
>
> 「フォーム項目」タブの `選択肢・注意` 列には `［モバイル端末ページ］` のように
> どのページ配下かが出る。

### 選択肢（2026-09-07 時点）

**正本は「フォーム項目」タブの `選択肢・注意` 列。** 下の表は目安。

| 項目 | 値 |
| --- | --- |
| 検知したデバイス | `PC` / `モバイル` |
| アプリ種別（PC） | `ブラウザ` のみ |
| OS | `Mac` / `Windows` |
| 再現デバイス（複数可） | `iOS` / `Android` / `PC（ブラウザ）` |
| バグ検知環境 | `IT` / `STG` / `UT` / `STG02` / `本番` |
| インシデントレベル | `Lv.3` / `Lv.2` / `Lv.1` |
| 本番環境での再現有無 | `再現する` / `再現しない` / `新規機能のため確認不要` |
| フロントNGフラグ | `フロントNGである` / `フロントNGでない` |
| リリースSprint（起票時） | `Sprint 19` / `Sprint 19.1` / `Sprint 20` / `Sprint 20.1` / `Sprint 21` / `Sprint 21.1` |

> [!WARNING]
> **過去の回答から選択肢を推測しない。** 回答シートには 1999 件の実回答があるが、
> それは**当時の選択肢**で、フォームは編集されている。
> `ITテスト`（過去 446 件）も `ケース内NGのため確認不要` も `PC（アプリ）` も
> `デスクトップ` も、**もう選択肢に無い。**
> **`リリースSprint` は `Sprint 21`（半角スペース有り・`.0` なし）。**

### テスト種別 は 4 レイヤーに対応している

`テスト種別` の選択肢は、ケースのレイヤー接頭辞とそのまま対応する。**迷わずここで決める。**

| ケースの接頭辞 | テスト種別 |
| --- | --- |
| `SPEC-*`（画面仕様）/ `NFR-*`（非機能）| `STG/UTテスト(フロント)` |
| `SCN-*`（業務シナリオ）| `STG/UTテスト(ユーザーストーリー)` |
| `MB-*`（ミドルバック）| `STG/UTテスト(ミドルバック)` |
| ケース外で見つけたもの | `STG/UTテスト_ケース外` |

E2E では使わない残りの選択肢: `リグレッションテスト` / `リグレッションテスト_ケース外` /
`新規エラーログの潰しこみ` / `クラッシュの潰しこみ` / `モンキーテスト` / `仕様質問` / `調査からの起票`

> [!WARNING]
> **`バグ検知環境` に「ローカル」が無い。** ローカル実施の NG をどう分類するかは
> 運用の決めごと。暫定で `UT` にしている。

## 【E2E】NG管理ブックの列

1 行 = 1 件の NG。見出しは 4 行目、データは 5 行目から。

**列はフォームの質問と同じ並び順にしてある。** 順番が違うと、フォームと突き合わせながら
埋めるときに毎回目が迷う。

| 列 | 内容 | 扱い |
| --- | --- | --- |
| `A`〜`W` | フォームの 22 項目（フォームの並び順） | フォームへ送る |
| `A`〜`J` | お名前 / 検知したデバイス / アプリ種別 / OS / モバイル系 / 再現デバイス | **空でよい。** `固定値（既定）` が入る |
| `K`〜`O` | テスト種別 / バグ検知環境 / 本番環境での再現有無 / インシデントレベル / 開発対象ID | 選択式はドロップダウン |
| `P` `Q` | **テストケースリンク（ケースPR）/（実施記録シート）** | フォームは 1 項目。**両方を改行で連結して送る** |
| `R`〜`W` | NG事象 / 再現方法 / 証跡 / 事象が起きている時間 / フロントNGフラグ / リリースSprint | |
| `X`〜`AE` | 起票日 / 機能名 / 発見元ケース / 期待する結果 / 実際の結果 / 原因・解消方針 / 検出元PR / GitHub Issue | **（内部）フォームに送り先が無い** |
| `AF` | **送信** | ← チェックしてからメニューを押す |
| `AG`〜`AI` | 送信済み日時 / フォーム回答ID / 送信エラー | スクリプトが書く |

- **`NG ID` は置かない。** 行を一意に指すのは行番号とフォーム回答IDで足りる
- **`NG事象`(R) に 事象 + 期待値 + 実際 を畳んで書く。** フォーム側に期待値と実際の欄が無い
  （`AA` / `AB` はブック内の控え）

### 「フォーム項目」タブ

| 列 | 内容 |
| --- | --- |
| `A`〜`E` | # / 項目タイトル / タイプ / 必須 / itemId（スクリプトが書く）|
| `F` | **対応する列** — NG一覧 の列記号。カンマ区切りで複数指定できる（`P,Q`）|
| `G` | **固定値（既定）** — その列が空のときに送る値 |
| `H` | 選択肢・注意 — フォームの実際の選択肢。**ここが正本** |

> [!IMPORTANT]
> **`対応する列` と `固定値` は別の列に分ける。**
> 同じ列に `F` と `"PC"` を混ぜていたため、どちらの意味かが読めず、
> スクリプトが引用符の有無で推測していた。分けたことで
> **「列が空なら固定値」= 固定値が既定値としてはたらく**という明確な意味を持たせられた。

> [!WARNING]
> **`=HYPERLINK("url","ラベル")` のセルは `getValues()` だとラベルしか返らない。**
> リンク列（テストケースリンク・証跡）で URL を送るため、
> `getFormulas()` と `getRichTextValues()` から URL を取り出す。

## セットアップ（人がやる。初回だけ）

1. 拡張機能 → Apps Script に [`apps-script/NGForm.gs`](../apps-script/NGForm.gs) を貼って保存
2. ブックを開き直す（`NGフォーム` メニューが出る）
3. **フォームの項目を取得する** — 承認画面 →「詳細」→（安全ではないページ）に移動 → 許可
4. 「フォーム項目」タブの `対応する列` と `固定値（既定）` を確認

## 送信できないとき

**エラーは「送信エラー」列とダイアログの両方に出る。** 項目名・送った値・由来の列・許容値が入る。

```
問題があるので 1 通も送りませんでした（1 / 2 行）。
フォームの回答は取り消せないため、途中まで送りません。

6 行目
  ・選択肢に無い値です: 「バグ検知環境」に "IT環境" を送ろうとしました（L列）
      選択できるのは: IT / STG / UT / STG02 / 本番
```

| メッセージ | 直し方 |
| --- | --- |
| `必須なのに空: 「〜」` | その列が空。中途半端な回答をフォームに残さないため送らない |
| `選択肢に無い値です: 「〜」` | 許容値がメッセージに出る。ドロップダウンから選び直す |
| `項目が見つからない: 「〜」` | フォームの質問が変わった。**フォームの項目を取得する**を押す |
| `フォームを開けませんでした` | B4 が回答用 ID か、編集権限が無い。**B4 を空にして取得し直すと自動で引く** |
| `チェックが入った行はすべて送信済みです` | 再送するなら `AG` と `AH` を消す |

### 表記ゆれは自動で吸収する

前後の空白・全角半角・大文字小文字の違いは NFKC 正規化して照合し、
**フォーム側の正式表記に直してから送る。** 「選択肢にあるのに無効と言われる」の大半はこれで消える。
`CHECKBOX` と「その他あり」の項目は選択肢外の入力を許す。

### そもそも打てないようにする

選択式の列にはフォームの選択肢そのものをドロップダウンにしてある。
選択肢が変わったら **フォームの項目を取得する**を押せば追随する。

## 1 行でも問題があれば 1 通も送らない

`sendChecked` は**全行を組み立てて検証してから**送る。

**フォームに投稿された回答は取り消せない。** 途中まで送るのが最悪の結果になる
（誤投稿が組織の NG 一覧に残り、人が手で消すしかない）。
実際に検証用のテスト投稿 4 件を残してしまった。

> [!WARNING]
> **かつて 1 行から 2 通投稿された。** `LockService` で直列化していたが、
> `setValue` は実行の終わりまで反映が遅延されるため、
> A がロックを解放した時点で B から見た `送信済み日時` はまだ空だった。
> 「読む → 送る → 書く」の順では排他が成立しない。
>
> 現在は `onEdit` トリガーを廃止して単一の入口にし、送信のたびに
> `SpreadsheetApp.flush()` で確定させている。

## AI がやること / やらないこと

- **やる**: `NG一覧` に行を書く（Sheets API）。承認不要
- **やらない**: `AF列` のチェックとメニューの実行。**投稿の判断は人が持つ**

**送信済みの行は再送されない。** 直すときは `AG`（送信済み日時）と
`AH`（フォーム回答ID）を消してからチェックし直す。
